# Phase 4 — UI Design Contract

> Visual and interaction contract for the professional app: KYC, availability, offers inbox, job execution (arrive → OTP → complete), plus the customer-side OTP display and booking-tracking screens deferred from Phase 2. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Source of truth:** the already-implemented customer/catalogue UI is the de-facto design system (no `04-CONTEXT.md` exists). Every value below was read from the repo — `app/globals.css`, `tailwind.config.ts`, `components.json`, `components/auth/RoleShell.tsx`, `components/catalogue/**`, `lib/status.ts`, `app/professional/page.tsx` — not invented. Phase 4 **extends** these patterns; it does not introduce a new visual language.

## Spacing Scale

Tailwind's default scale as used across the existing app — all values are multiples of 4:

| Token | Value | Usage (observed in repo) |
|-------|-------|--------------------------|
| xs | 4px | Icon gaps (`gap-1.5`≈6px is the only sub-4 optical nudge allowed, already in use), inline padding |
| sm | 8px | Compact element spacing (`gap-2`), badge padding (`px-2.5 py-0.5`) |
| md | 16px | Default element spacing (`gap-4`, `space-y-4`), card inner rhythm (`mt-4`) |
| lg | 24px | Section padding (`p-6` cards), grid gaps (`gap-6`) |
| xl | 32px | Layout gaps (`gap-8` shell columns) |
| 2xl | 48px | Major section breaks, empty-state vertical padding (`py-12` = 48px) |
| 3xl | 64px | Page-level spacing (shell `py-8` doubles via 32px block rhythm; keep for page intros) |

Card convention: `rounded-xl border border-gray-200 bg-white p-6` (observed on every `app/professional/page.tsx` section and catalogue card). Buttons: `rounded-lg px-4 py-2 text-sm font-semibold`.

**Exceptions:**
- **Touch targets (phone-first job flow):** primary job-execution controls — Accept / Decline / Confirm arrival / Start job / Complete job — must be `min-h-11` (44px) even where the padding pattern would yield ~36px. Icon-only controls: 44×44px hit area minimum.
- **OTP slots** keep `input-otp`'s `h-10 w-10` (40px) boxes; the wrapping control gets the 44px target.
- No other exceptions. No 2px/6px/10px/12px custom spacing values.

## Typography

Inter (existing). Four sizes, two weights:

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Label / meta | 12px (`text-xs`) | 600 (semibold) | 1.4 | Eyebrows, badge text, timestamps, table meta, hints |
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 | **Default for everything** — paragraphs, list items, form inputs, empty-state copy (observed 161× `text-sm` vs all others) |
| Subheading | 16px (`text-base`) | 600 (semibold) | 1.3 | Section titles inside cards (`<h2 className="text-base font-semibold text-gray-900">`) |
| Heading / page title | 24px (`text-2xl`) | 600 (semibold) | 1.2 | RoleShell `<h1>`; screen headings on new pages |

Weights: exactly **400 and 600**. Pre-existing deviation noted: RoleShell's h1 ships `font-bold` (700) today — Phase 4 does not restyle the shared shell (regression risk for customer/admin screens); all **new** headings use 600.

**Numeric display exception:** countdown timers, the 4-digit OTP code, and earnings/rating figures use `text-3xl (30px) font-semibold tabular-nums` with `font-variant-numeric: tabular-nums` (`tabular-nums` class — already used in `PriceBreakdown`). This is the only size above the four-role scale, and it is reserved for large numerals — never prose.

Emphasis inside body copy: `font-semibold` only. Never italic, never underline except links.

## Color

Tokens from `app/globals.css` [VERIFIED]:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`--background: 0 0% 100%`) | Page/card/panel surfaces. The canvas behind cards is gray-50 `#F9FAFB` (`bg-gray-50` in RoleShell) — together white + gray-50 is the neutral field that must stay ≥60% of every screen |
| Secondary (30%) | `#F9FAFB` / gray-100 `#F3F4F6` (`--secondary`/`--muted: 210 40% 96%`) | Shell canvas, secondary buttons (`bg-gray-100`), muted rows, skeleton bases, nav hover fills |
| Accent (10%) | Blue-600 `#2563EB` (`--primary: 221 83% 53%`; also the PWA `themeColor`) | **Reserved list below** |
| Destructive | Red-600 `#DC2626` (`--destructive: 0 84% 60%`) | Destructive confirm buttons and destructive-only icons — nothing else |
| Success | `#16A34A`-family (`--success: 142 71% 45%`) | Success confirmations only (e.g. hours saved) |
| Warning | Amber (`--warning: 38 92% 50%`) | The KYC "In review"/gate banner (already shipped amber-50/amber-600 pattern on professional home) |

**Accent (`blue-600`) is reserved for — explicit list:**
1. Primary CTA buttons (Accept offer, Confirm arrival, Start job, Complete job, Upload documents, Save hours)
2. Active nav item in RoleShell (`bg-blue-50 text-blue-700`) and the eyebrow label (`text-blue-600`)
3. Focus-visible rings (`focus-visible:ring-blue-500`)
4. Inline links and the EmptyState action button
5. The SmartHelp logo tile (`bg-blue-600`)

Never: large background fills, body text, status colours, decorative gradients. If a screen reads "mostly blue", it violates the contract.

**Status colours are NOT the accent and are NOT free choice.** Booking status badges come exclusively from `statusPresentation`/`TONE_CLASSES` in `lib/status.ts`: neutral `bg-muted`, info `bg-sky-100 text-sky-900`, progress `bg-amber-100 text-amber-900`, success `bg-emerald-100 text-emerald-900`, warning `bg-orange-100 text-orange-900`, danger `bg-red-100 text-red-900`. KYC status chips reuse the VERIFICATION_COPY tones already on professional home (gray/amber/green/red 100→800/900 pairs). **No colour-only status** — every badge keeps its sr-only description (§31.2, already implemented in `BookingStatusBadge`).

**No refund UI anywhere** (hard rule): `refund_pending`/`refunded` badges may *display* on customer tracking (they come from `lib/status.ts`), but Phase 4 ships no refund actions, buttons, or confirmation flows.

## Copywriting Contract

Voice: plain, second-person, sentence case, Indian English (`₹`, "verification" not "KYC" in customer-facing prose). Existing repo copy is the authority (`EmptyState`, `BookingStatusBadge` descriptions, professional home VERIFICATION_COPY).

### Primary CTAs (verb + noun, per screen — these are the phase's action labels)

| Screen | Primary CTA | Notes |
|--------|-------------|-------|
| Offers inbox | **Accept offer** | Secondary: **Decline** (ghost/outline, not red) |
| Job detail → on_the_way | **Confirm arrival** | Geofence pass OR manual override (override requires reason) |
| Job detail → arrived | **Start job** (after OTP entry) | Disabled until 4 digits entered |
| Job detail → in_progress | **Complete job** | Enabled at timer 0 or early with confirmation |
| KYC page | **Upload documents** → **Submit for review** | Matches existing home-page button label |
| Availability page | **Save hours** / **Go online** / **Go offline** | Online toggle is a Switch + label, not a button |
| Customer tracking (OTP card) | **Get a new code** | Regenerate — max 3, disabled with helper text at cap |

Success toasts (react-hot-toast, top-center): `Offer accepted. The job is in your schedule.` · `Arrival confirmed.` · `Job completed.` · `Hours saved.` · `Documents submitted for review.`

### Empty states (use `EmptyState` — heading + body + next step)

| Where | Heading | Body |
|-------|---------|------|
| Offers inbox, no open offers | **No offers right now** | New jobs appear here as they come in. Keep yourself online to get them. |
| Today's jobs, none accepted | **No jobs today** | Accepted jobs for today will appear here. Check the offers tab for new work. |
| Time off, none booked | **No time off booked** | Days you block will appear here. Add a date to stop offers on that day. |
| Earnings (if shipped) | **No earnings yet** | Earnings appear after your first completed job. |
| KYC not started | handled by existing VERIFICATION_COPY `not_submitted` blurb — do not duplicate | — |

### Loading copy

Pattern (already in repo): spinner + text, `role="status"` — `Loading this job…`, `Loading offers…`, `Saving…` on the pending button (`aria-busy`).

### Error states (problem + what to do next; never raw codes)

| Situation | Copy |
|-----------|------|
| Generic fetch failure | **We could not load {this page\|your offers\|this job} right now.** Pull down to retry, or try again in a moment. |
| Offer already taken (409 `ASSIGNMENT_TAKEN`) | **This job was just accepted by someone else.** It has been removed from your inbox. *(auto-remove card + toast, no modal)* |
| Schedule overlap on accept (409 `PROFESSIONAL_UNAVAILABLE`) | **That time overlaps another job.** Your offer could not be accepted — refresh to see current offers. |
| Version conflict (409 `STALE_VERSION`) | **This job changed on another device.** We refreshed it — check the latest status and try again. |
| OTP failure (wrong/expired/locked — **one generic message**, spec §10.1/Pitfall 5) | **Invalid or expired code.** Ask the customer for the current code, or request a new one if it has expired. *(never reveal which check failed; attempts are counted locally by the UI — after 3 visible failures append: Too many attempts — try again in 15 minutes.)* |
| Upload rejected (size/MIME) | **That file could not be uploaded.** Use a photo or PDF under 5 MB. |
| Offline / poll failure | silent — keep last data, show a small `Connection lost — retrying…` amber inline chip near the page title; never blank the screen |

Field errors under inputs: 12px `text-red-600`, `aria-invalid` + `aria-describedby`.

### Destructive actions (each + confirmation approach)

All use the existing `components/ui/ConfirmationDialog`. Nothing destructive executes on first tap.

| Action | Type | Confirmation copy |
|--------|------|-------------------|
| **Decline offer** | warning | *Decline this job?* — You will not be offered this job again. This is recorded on your response history. `[Keep offer]` `[Decline job]` |
| **Cancel / no-show a job** (pro-initiated) | danger | *Cancel this job?* — The customer will be notified and this is recorded against your account. A reason is **required** (select before confirm enables). `[Go back]` `[Cancel job]` |
| **Replace a KYC document** | warning | *Replace this document?* — Verification restarts from the beginning for all documents. `[Keep document]` `[Replace]` |
| **Delete time-off day** | info | *Remove time off on {date}?* — Offers may be sent for that day again. `[Remove]` |

No refund action, no refund copy, no payment-amount edit controls anywhere in this phase.

## Interaction Contracts

| # | Contract |
|---|----------|
| 1 | **Polling, never Realtime.** Offers inbox: 5s (`/api/professionals/offers`). Customer track + job detail timer: 15s (`/api/bookings/:id/track`). Both: `useEffect` with `clearInterval` cleanup on unmount, abort in-flight fetch, no overlapping requests (skip tick if prior in-flight), pause polling when `document.hidden` and refresh immediately on visibility return. No `supabase.channel()` (Phase 7). |
| 2 | **Server-authoritative timer.** Render `remaining = endsAt − serverNow`, re-anchored from payload each poll. `tabular-nums`, `mm:ss`. `Date.now()` deltas forbidden (§22.3). At 0: show **Time's up** state with the Complete job CTA emphasized (completion still requires pro confirmation). |
| 3 | **Inbox red dot.** Unread-open-offer count derives client-side from the 5s poll → red dot (`h-2 w-2 rounded-full bg-red-600`) on the **Jobs** item in RoleShell nav, with `aria-label="N open offers"`; `aria-live="polite"` on the count so screen readers hear increments, **not** on the poll itself. |
| 4 | **Optimistic UI: none for job transitions.** Accept/arrive/OTP/complete are server-authoritative — button shows `aria-busy` + spinner while in flight, UI updates only from the response. Double-tap disabled via the disabled state. (Optimistic toggles are allowed only for the availability Switch, rolled back on error.) |
| 5 | **Status rendering is single-sourced.** Every status label/chip/timeline comes from `lib/status.ts` `statusPresentation`. The job stepper derives from `CUSTOMER_LADDER`/`step` — the UI may not offer an action the state machine forbids (same pattern as `isReschedulableStatus`). |
| 6 | **Privacy gates in the UI.** Offer cards show locality-level info only (no phone, no full address, no customer name detail beyond first name) until accept — then the job detail reveals address + navigate link. `otp_hash` never exists in any client payload (enforced server-side; UI asserts nothing about it). |
| 7 | **OTP entry:** 4-digit `InputOTP`, auto-submit on 4th digit, `inputMode="numeric"`, `autocomplete="one-time-code"` off (it's the *customer's* code, not SMS). Wrong code clears the slots and focuses the first slot. Never prefill, never log. |
| 8 | **Customer OTP display:** shown only when `status === 'arrived'` (mint-at-arrived), 30px tabular numerals + `Expires in mm:ss` countdown; on expiry → Get a new code (cap 3 → helper text `New code limit reached — ask support.`). |
| 9 | **KYC upload:** file picker → client-side pre-check (≤5MB, MIME allow-list) → signed-URL upload with progress → `status='submitted'` row. Per-document status chip from VERIFICATION_COPY. Stepper shows the three steps (Identity / Address / Selfie) with per-step state; never show internal reviewer notes (§20.10). |
| 10 | **Toasts** for one-shot success/failure feedback (top-center, existing Toaster); inline banners for persistent state (KYC gate amber banner pattern already shipped — reuse it verbatim for `submitted`/`rejected` gates on every professional page that requires verification). |
| 11 | **Verification gate:** unverified professionals see the amber banner + KYC CTA and cannot access job-execution actions (buttons disabled with explanatory helper text, not hidden). |
| 12 | **Accessibility floor:** skip-link (already in RoleShell) works on all new pages; focus-visible ring on every interactive element; `role="status"` loading regions; no colour-only status; touch targets ≥44px in the job flow; errors announced via `aria-live="assertive"` on submit failures. |
